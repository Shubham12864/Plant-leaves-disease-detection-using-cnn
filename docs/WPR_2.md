## Work done this week

One training protocol was frozen so that four architectures could be compared on
the same footing. A pilot ran one epoch of each on two T4 GPUs to check memory and
speed before committing GPU hours to a full sweep. All four fitted without running
out of memory; EfficientNet-B0 took 2.45 minutes per epoch and ConvNeXt-Tiny 3.15.

The training engine was hardened for unattended use. It now resumes from a
checkpoint, refuses to resume when the dataset fingerprint has changed, refuses to
resume when hyperparameters differ, and records the learning rate applied at each
epoch. Notebooks are generated by builder scripts that embed the engine and the
protocol byte for byte, so a hand-edited cell cannot drift away from the
repository version.

The first full sweep ran twelve trainings across four architectures and three
seeds.

## Findings

The sweep came back unusable. EfficientNet-B0 reached 0.68 to 0.72 validation
accuracy where the reference model was at 0.995, ResNet18 0.07 to 0.58, SmallCNN
0.15 to 0.23. Only ConvNeXt-Tiny came close, at 0.94 to 0.95.

I measured how far each trained model sat from the ImageNet weights it started
from. The reference model had moved 1.96%. The EfficientNet-B0 sweep run (seed 42)
had moved 0.49%, so the backbone had barely trained and only the final layer had
learned.

Four protocol settings explain it, each checked against the original script: weight
decay 500 times stronger (0.05 against 1e-4), global batch size four times larger
(128 against 32), a decaying learning-rate schedule whose last epoch ran at 1% of
the nominal rate, and added label smoothing and class weights.

## Problems

The sweep cost 5.6 GPU hours and produced nothing quotable. The cause was not
obvious from the configuration, which is what made it expensive: the nominal
learning rate had gone up, not down. I am treating this as a methodology finding
rather than hiding it, and the archive is retained with the numbers marked invalid.

Every run was also about 4.5 times slower than the pilot predicted for most
architectures (EfficientNet-B0 3.1 times). The cause is not visible in the
artifacts and is recorded as unexplained.

## Next week

Restore the proven optimisation settings, put a short validation gate in front of
any long run, and re-run the sweep only after the gate passes.
