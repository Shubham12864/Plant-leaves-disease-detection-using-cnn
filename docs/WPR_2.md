## Work done this week

One training protocol was frozen in `configs/protocol_v2.json` so that four
architectures could be compared on the same footing. A pilot ran one epoch of each
on two T4 GPUs to check memory and speed before committing GPU hours to a full
sweep. All four fitted without running out of memory; EfficientNet-B0 took 2.45
minutes per epoch and ConvNeXt-Tiny 3.15.

The training engine was hardened for unattended use. It now resumes from a
checkpoint, refuses to resume when the dataset fingerprint has changed, refuses to
resume when hyperparameters differ, and records the learning rate applied at each
epoch. Notebooks are generated by builder scripts that embed the engine and the
protocol byte for byte, because a hand-edited cell had already drifted once and
caused a failure that only appeared on Kaggle.

The first full sweep ran twelve trainings across four architectures and three
seeds.

## Findings

The sweep came back unusable. EfficientNet-B0 reached 0.68 validation accuracy
where the reference model was at 0.99, ResNet18 0.58, SmallCNN 0.23. Only
ConvNeXt-Tiny trained properly, at 0.95.

I measured how far each trained model sat from the ImageNet weights it started
from. The reference model had moved 1.96%. The broken sweep runs had moved 0.49%,
so the backbone had barely trained at all and only the final layer had learned.

## Problems

The sweep cost 5.6 GPU hours and produced nothing quotable. The cause was not
obvious from the configuration, which is what made it expensive: the nominal
learning rate had gone up, not down. I am treating this as a methodology finding
rather than hiding it, and the archive is retained with the numbers marked
invalid.

## Next week

Find the real cause, put a short validation gate in front of any long run, and
re-run the sweep only after the gate passes.
