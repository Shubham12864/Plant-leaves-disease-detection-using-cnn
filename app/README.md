# Leafread frontend

A static frontend for the BT40 leaf disease project. No build step, no framework, no server required:
open the HTML files directly, or serve the folder with any static server.

```
app/static/
  index.html          landing page, one recorded case inline
  scan.html           single photo: file, camera, staged loading, result, Grad-CAM slider
  upload.html         batch: queue, per image progress, summary tiles, table, CSV
  inference.html      one case in full: all 38 class scores, per stage timing, checkpoint, API JSON
  css/app.css         landing tokens and components
  css/app-pages.css   app page layouts (scan, batch, inference)
  css/inference.css   the 38 class ranking list and the JSON block
  js/ui.js            shared nav, scroll reveals, tagline, bars, model card
  js/api.js           inference client, POST /api/predict
  js/scan.js          scan page behaviour
  js/upload.js        batch page behaviour
  js/inference.js     inference page behaviour
  js/app.js           landing page behaviour
  js/demo-data.js     GENERATED, do not edit
  js/config.example.js  set window.LEAFREAD_API to talk to a real backend
  assets/             recorded leaf photos and Grad-CAM overlays
```

## Running it

Open `index.html` in a browser. That is the whole setup.

For the camera on the scan page, browsers only grant `getUserMedia` on `localhost` or `https`, so serve
the folder instead of opening the file:

```
python -m http.server 8080 --directory app/static
```

The camera button reports the browser's refusal in the page rather than failing silently.

## Demo mode and live mode

`js/demo-data.js` is generated by `scripts/make_demo_assets.py` from the EfficientNet-B0 checkpoint.
It contains real predictions and real Grad-CAM overlays for held out test images, plus a recorded batch
of twelve. With no backend configured the pages replay those, labelled `demo mode` in the header.

To use a real service, copy `js/config.example.js` to `js/config.js`, set the base URL, and load it before
`js/api.js`. The contract the frontend expects:

```
POST /api/predict     multipart/form-data, field "file"
  -> { prediction: { label, crop, condition, probability, confident },
       top3: [{ label, crop, condition, probability }],
       gradcam: { png_base64, target_layer, alpha },
       timing_ms: { preprocess, forward, gradcam, total },
       warnings: [], model: { architecture, image_size, classes, ... } }

GET /api/model        -> { architecture, image_size, classes, val_macro_f1, confidence_threshold, ... }
```

Both paths converge on the same view model in `js/scan.js`, so nothing visual changes when the backend
arrives. Files that cannot be classified say so: no label is ever invented for a user photo.

## Honesty rules this frontend holds

- A demo heat map is never drawn over a user's own photo.
- A user photo is never given a prediction in demo mode.
- Every number on screen comes from the checkpoint, and `demo-data.js` records the images it came from.
- The result panel always shows three candidates and the confidence threshold, because a near tie is the
  interesting case.

## Regenerating the demo assets

```
.venv-smoke/Scripts/python.exe scripts/make_demo_assets.py --sample 250 --batch 12
```

That sweeps the locked test split, picks a representative confident case, a real misclassification, and
records the batch. It writes `assets/` and `js/demo-data.js`.
